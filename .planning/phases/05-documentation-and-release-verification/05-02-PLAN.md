<objective>
Create wiki-ready OCI DNS provider guidance for maintainers to publish upstream.

Purpose: Give users a practical setup guide for delegated subzones, API-key
auth, resource-principal fallback, policies, secret handling, and deferred live
validation without bloating in-repo DNS docs.
Output: `05-OCI-DNS-WIKI.md` with copy-ready guidance and placeholders only.
</objective>

<threat_model>
T-05-04: Users could configure RP env while a complete API-key config is still
present and misunderstand why API-key auth wins.
Mitigation: Put auth precedence in the overview and both setup recipes.

T-05-05: Operators could grant broader OCI DNS access than needed.
Mitigation: Use minimal `read dns-zones` plus `use dns-records` examples and
explicitly call them adaptable starting points.

T-05-06: A wiki artifact could imply live OCI validation passed for v1.
Mitigation: State v1 proof is mocked/static and point future live checks to the
separate v2 checklist created by Plan 05-03.
</threat_model>
