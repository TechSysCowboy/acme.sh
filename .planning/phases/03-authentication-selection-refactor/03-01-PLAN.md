<objective>
Introduce the Phase 3 authentication selector boundary while preserving the
current API-key signing path.

Purpose: Make auth mode selection explicit before Phase 4 adds RP signing,
without changing public `dns_oci_add` / `dns_oci_rm` behavior for existing
API-key users.
Output: `_oci_auth_mode` selector support in `dnsapi/dns_oci.sh` plus mocked
public tests for API-key primary behavior and RP not-implemented boundary.
</objective>

<threat_model>
T-03-01: The selector could accidentally prefer resource principal over complete
API-key config and break existing users.
Mitigation: `_oci_select_auth` must call `_oci_config` first and tests must
prove complete API-key config still reaches mocked PATCH.

T-03-02: Resource principal fallback could proceed into the old API-key signer
with missing key fields.
Mitigation: `_signed_request` must gate on `_oci_auth_mode=resource_principal`
before fingerprint/signature work and return a stable not-implemented error.

T-03-03: Selector state could be lost through command substitution.
Mitigation: Store mode in a process-local private global and assert
`_oci_auth_mode=resource_principal` in the fallback boundary test.
</threat_model>
